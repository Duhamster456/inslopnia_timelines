## Файлы

| файл | назначение |
|---|---|
| `timeline.py` | CLI журнала, модель, рендеры text / html / json / jsonl / sqlite, импорт прогона харнесса, `transcript`, `validate` |

## Что показывает HTML-таймлайн

- **Шапка:** заголовок, вердикт, строка «задача · модель · время», пять KPI (длительность, токены и стоимость, узлы DAG, инциденты, гипотезы), флаг и резюме. Детали (in/out/cache, фазы) — во всплывающих подсказках.
- **Дорожки агентов**, по одной на агента. Полосы активности окрашены статусом узла: выполняется, готово, провал, отменён. На дорожках стоят маркеры событий, у каждого типа своя форма; чипы над таймлайном скрывают и показывают типы. Роль подписана бейджем, под именем — токены и стоимость, в подсказке — модель и время активности. Ромбы — правки DAG на дорожке автора правки. Пунктирные кривые P→E показывают поручения, старты и отмены. Отдельно показаны стрелки сообщений и полосы фаз.
- **Графики под дорожками** на той же оси: накопленные токены стеком по ролям и прогресс DAG (узлы по статусам).
- **DAG со скраббером** показывает граф в момент курсора. Ещё не добавленные узлы видны пунктирными «призраками», последний изменённый узел обведён, статус написан в самом узле. Рядом список ревизий, кнопки ◀ ▶ и ▶ play.
- **Общий курсор.** Клик по таймлайну, ревизии, инциденту или строке журнала переносит курсор, и DAG перерисовывается. Клик по агенту или узлу включает фокус на шаге: остальное приглушается.
- **Ниже:** карточки инцидентов и гипотез, журнал событий с поиском и фильтрами. Подробности открываются в боковой панели, Esc её закрывает.
- **Кнопки таймлайна** (связи, − / Fit / +, снять фокус) стоят в его заголовке, масштаб меняется и через Ctrl+колесо.

Страница — один файл без внешних зависимостей, работает офлайн.

## GUI: Timeline Explorer

```bash
python gui.py [<папка|файл> …] [--port 8780] [--open]
```

`gui.py` — локальный сервер на stdlib, слушает только `127.0.0.1`. Всё рендерит сам `timeline.py`, импортированный как модуль, поэтому любое улучшение утилиты сразу видно в GUI.

| раздел | что показывает |
|---|---|
| Обзор | сводные цифры, исходы, «длительность × токены», инциденты по категориям, сортируемая таблица сессий. Открывается пунктом «Обзор» вверху боковой панели или кликом по логотипу |
| Таймлайн | HTML-рендер во фрейме; меню «⤓ экспорт»: новая вкладка, HTML, JSONL |
| Текст | `render text` с выбором секций и детализации |
| Анализ | `ANALYSIS.md` рядом с базой; вкладка есть, только если файл есть |
| Проверка | `validate`: ERROR и WARN |
| SQL | запросы к базе только на чтение; пресеты по представлениям; `:s` = текущая сессия; Ctrl+Enter |

Открытая вкладка хранится в URL (`#s=…&db=…&tab=…`). Индекс пересканируется раз в 30 с и по кнопке ⟳.

### Открыть папку или файл

Кнопка с папкой в шапке (или Ctrl+O) открывает диалог. Режим вверху: «Открыть вместо текущих» заменяет источники, «Добавить к текущим» дописывает к ним.

| способ | что делает |
|---|---|
| поле пути | вставьте путь к папке или файлу и нажмите Enter; кавычки от «Копировать как путь» можно оставить |
| обзор (справа) | браузер файловой системы: диски, «домашняя», «рабочая», хлебные крошки. Подпапки помечены «есть .db» или «прогон харнесса», у файлов видны тип и число сессий |
| «Выбрать папку… / файл…» | системный диалог ОС (tkinter в дочернем процессе; без tkinter кнопок нет) |
| перетаскивание | бросьте файл или папку в окно. Браузер не сообщает настоящий путь, поэтому на сервер уходит **копия** в `%TEMP%/timeline-gui/uploads`, без живого обновления; при перезапуске копии удаляются |
| недавние | последние 10 путей (хранятся в `localStorage` браузера) |

Что считается таймлайном:

- **папка** сканируется рекурсивно на БД `render sqlite`. Пропускаются `workspace`, `sessions`, `pi-sessions` и скрытые папки, всего не больше 20 000 папок;
- **файл** — БД `render sqlite`, JSONL-журнал или `ledger.sqlite3` харнесса. Журнал и ledger рендерятся на лету в кэш `%TEMP%/timeline-gui/derived` и перестраиваются при изменении файла (у ledger учитывается и `-wal`), поэтому идущий прогон обновляется сам;
- **папка прогона харнесса** (в ней лежит `ledger.sqlite3`) открывается как этот прогон;
- **папка с прогонами** (например, `ctf-runs/`): если таймлайн-БД нет, а `ledger.sqlite3` есть, прогоны импортируются автоматически. Импортировать их рядом с БД можно ссылкой «+ N прогонов харнесса» у источника в диалоге.

Одна сессия из разных файлов (например, `timeline.db` агента и `ledger.sqlite3` того же прогона) показывается один раз, файл-источник выбирается в шапке сессии. Если источников несколько, в боковой панели появляется фильтр по источнику; обзор его учитывает.

**Безопасность.** Сервер может открыть любой путь на машине. Поэтому он отвечает только на `Host` = `127.0.0.1` / `localhost` (защита от DNS rebinding), а POST принимает только со своего `Origin` и с `Content-Type` JSON или octet-stream, чего обычная форма с чужого сайта отправить не может (CSRF).

## Импорт прогона inslopnia_harness

```bash
python timeline.py -f timeline.jsonl import-harness <ctf-runs/<task>/run> [--bucket 60] [--merge]
```

Источники в `ledger.sqlite3`:

- `step_added`, `step_updated`, `step_started`, `step_done`, `step_failed`, `step_cancelled` → правки и статусы DAG (`by`: planner / operator / runtime);
- `step_report`, `executor_answer`, `exec_directive`, `operator_*` → события и сообщения со стрелками;
- `step_failed`, `stale_*_killed` и аварийный `planner_turn_end` → автоинциденты (категорию стоит перепроверить, см. AGENTS.md §7);
- `run_finished` → вердикт и флаг (из строки `FLAG:`).

Токены и стоимость берутся из `usage` в `pi-sessions/*.jsonl` и агрегируются по агентам бакетами `--bucket` секунд. Используются именно они, а не `step_progress`, потому что stdout pi на Windows иногда теряется. `--merge` переимпортирует прогон и сохраняет ручные записи.

## SQLite

```bash
python timeline.py -f a.jsonl render sqlite -o all.db --session-id run-a   # сессии складываются в одну базу
python timeline.py -f b.jsonl render sqlite -o all.db --session-id run-b
python timeline.py -f a.jsonl render sqlite -o all.db --fresh              # пересоздать файл базы
```

Без `-o` пишется `<журнал>.db`, без `--session-id` берётся имя файла журнала. Перерендер сессии заменяет только её строки, остальные сессии в базе сохраняются.

**Таблицы.** У каждой есть `session_id`; в событийных таблицах есть `t` (epoch) и `t_rel` (секунды от старта).

| таблица | содержимое |
|---|---|
| `sessions` | итог: вердикт, флаг, длительность, токены (in/out/cache), стоимость, счётчики узлов, инцидентов, гипотез, `meta_json` |
| `agents`, `agent_spans` | агенты с итогами по токенам и стоимости, интервалы активности |
| `nodes`, `node_deps`, `node_runs` | финальный DAG, рёбра, каждая попытка узла с длительностью |
| `dag_ops` | история правок DAG: `by_agent`, `prev_status` → `status` |
| `events` | лента событий: `agent` → `to_agent`, `kind`, `step` |
| `usage` | расход токенов с ролью агента |
| `hypotheses`, `hyp_history` | гипотезы и смена статусов |
| `incidents`, `incident_history` | инциденты; `time_to_resolve_s`, `auto` — автоинцидент импорта |
| `flags`, `outcomes`, `phases` | флаги, вердикты, фазы |
| `records` | сырые записи журнала (JSON), из них сессия восстанавливается без потерь |

**Представления.**

| представление | что показывает |
|---|---|
| `v_sessions_compare` | сравнение прогонов: вердикт, минуты, токены, $, узлы, инциденты, время до принятого флага |
| `v_timeline` | события и правки DAG одной лентой с `T+hh:mm:ss` |
| `v_agent_share` | доля агента в токенах и стоимости, токены за минуту активности |
| `v_role_totals` | итоги по ролям |
| `v_node_summary` | по узлам: статус, время выполнения, события, токены и $ шага, инциденты |
| `v_tokens_per_minute` | расход по минутам и ролям |
| `v_open_incidents` | открытые инциденты по важности |

```sql
SELECT * FROM v_sessions_compare;
SELECT node_id, status, run_s, tokens, cost FROM v_node_summary WHERE session_id = 'demo';
SELECT t_plus, agent, kind, title FROM v_timeline WHERE session_id = 'demo' AND kind IN ('milestone', 'error', 'dag_status');
```

**База как источник.** Любой рендер можно сделать из базы: модель, текст и HTML побайтно совпадают с рендером из исходного JSONL.

```bash
python timeline.py -f all.db sessions                                  # список сессий
python timeline.py -f all.db --session demo render html                # → all.demo.html
python timeline.py -f all.db --session demo render jsonl -o demo.jsonl # восстановить журнал
```

`--session` нужен, только если в базе больше одной сессии. Базу можно только читать; чтобы дописывать события, восстановите журнал через `render jsonl`.

## Дизайн и как его менять

Тёмная «ночная» тема с янтарным акцентом из логотипа и светлая «рассветная»; переключатель ◐ запоминает выбор. Заголовки набраны узким шрифтом, время и числа — моноширинным. Декора минимум, каждая цифра показана один раз.

Весь внешний вид задаётся в `theme.css`. Рендер и GUI встраивают его, логотип и favicon при сборке страницы (`timeline.apply_brand`), поэтому результат остаётся одним файлом, а стиль меняется в одном месте:

- **шрифты:** `--font-ui`, `--font-display`, `--font-mono`;
- **поверхности и текст:** `--page`, `--surface*`, `--ink*`, `--muted`, отдельно для ночи и рассвета;
- **акцент:** `--accent*`; например, `#4fd1c5` даст бирюзовую ночь;
- **цвета данных:** `--c-*` — категориальная палитра в проверенном порядке (различима при нарушениях цветового зрения); статусы `--good`, `--warning`, `--serious`, `--critical`;
- **форма:** `--radius*`, `--shadow*`.

Стили конкретных страниц лежат в `<style>` файлов `template.html` и `gui.html` и используют только токены, поэтому смена темы распространяется на них автоматически.

# inslopnia timelines

Таймлайны многоагентных сессий: что делал каждый агент, как планировщик менял план и раздавал шаги, где ушли время и токены, какие были гипотезы и сбои и чем всё кончилось.

Инструмент сделан для прогонов CTF-харнесса inslopnia_harness (планировщик P раздаёт шаги исполнителям E), но журнал можно вести для любой многоагентной сессии.

Что даёт:

- **для человека** — HTML-таймлайн и браузерный GUI: дорожки агентов, связи поручений, эволюция DAG, токены, инциденты;
- **для агента** — компактный текстовый дайджест сессии;
- **для анализа** — SQLite-база, в которую можно сложить много прогонов и сравнивать их SQL-запросами.

Нужен только Python 3.10+, сторонних пакетов нет.

## Посмотреть таймлайны

```bash
git clone https://github.com/Duhamster456/inslopnia_timelines.git
cd inslopnia_timelines
python gui.py examples --open                  # готовые примеры
python gui.py path/to/ctf-runs --open          # прогоны харнесса как есть
```

Откроется `http://127.0.0.1:8780/`. Слева список сессий, справа обзор или выбранная сессия.

- **Другие папки и файлы** открываются из самого GUI: кнопка с папкой в шапке или Ctrl+O. Там есть поле пути, обзор файловой системы и системный диалог. Файл можно просто перетащить в окно.
- **Что можно открыть:** папку с `timeline.db`, один `timeline.db` или `timeline.jsonl`, `ledger.sqlite3` харнесса или всю папку прогона.
- **Прогон харнесса без разметки** показывается сразу. Видно, что произошло технически: шаги, статусы, сообщения, токены. Объяснение того, почему так вышло, добавляет агент (следующий раздел).

Без сервера HTML можно отрендерить в файл: `python timeline.py -f examples/demo.jsonl render html -o demo.html`.

## Поручить агенту сделать таймлайн

Всё, что нужно агенту, описано в [AGENTS.md](AGENTS.md): формат журнала, команды, порядок разбора прогона, правила разметки, как классифицировать инциденты и что сдать. Подойдёт любой CLI-агент с доступом к shell и Python: Claude Code, Codex, pi.

**Один прогон харнесса:**

1. Заведите рабочую папку для результата, например `timelines/<task>/`. Агент прогон не меняет. Для подстраховки можно скопировать в рабочую папку `run/` (без `workspace/`) и `challenge.json` и указать в промпте `./run`.
2. Сохраните промпт в `prompt.txt` и запустите агента в рабочей папке:

   ```text
   Прочитай /path/to/inslopnia_timelines/AGENTS.md целиком и построй таймлайн в режиме A
   для прогона /path/to/ctf-runs/<task>/run. Рабочая папка — текущая. Работай автономно.
   ```

   ```bash
   cd timelines/codex
   claude -p "$(cat prompt.txt)"     # Claude Code: разрешите агенту запуск python и запись в папку (--allowedTools)
   pi -p "$(cat prompt.txt)"         # pi
   ```

3. Агент оставит в папке `timeline.jsonl`, `timeline.html`, `timeline.db` и `ANALYSIS.md`. Посмотрите результат: `python gui.py timelines --open`. Разбор будет на вкладке «Анализ».

**Много прогонов** — тот же промпт в цикле, по агенту на папку (запускать из корня репозитория):

```bash
REPO=$PWD
for run in /path/to/ctf-runs/*/run; do          # путь абсолютный: агент работает в другой папке
  task=$(basename "$(dirname "$run")")
  mkdir -p "timelines/$task"
  (cd "timelines/$task" && pi -p "Прочитай $REPO/AGENTS.md целиком и построй таймлайн в режиме A для прогона $run. Рабочая папка — текущая. Работай автономно." > agent.log 2>&1)
done
```

Агенты здесь идут по очереди. Для параллельного запуска поставьте `&` после закрывающей скобки и `wait` после цикла, а число одновременных агентов подберите под лимиты провайдера.

**Журнал своей работы.** Можно попросить агента вести таймлайн по ходу собственной многоагентной задачи (режим B в AGENTS.md): «Веди журнал этой сессии по <репозиторий>/AGENTS.md, режим B, файл `timeline.jsonl`».

**Качество разметки.** Слабые модели справляются с журналом, но часто приписывают сбои харнессу. В прошлых разборах из 28 таких инцидентов настоящими багами оказались 8. Поэтому категории инцидентов стоит перепроверять. Как это делать, агенту объяснено в AGENTS.md §7.
